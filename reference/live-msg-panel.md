# Live MSG-style message panel — Step 1

## Result
- DTS **Message** toggles a persistent preview beside the editor on wide screens; it stacks below on smaller screens. It stays open across term-sheet tabs.
- Black message body, amber envelope and field labels, UTC timestamp, live connection indicator, exact plain-text clipboard copy; no Bloomberg artwork or connection.
- Formatter reads saved BDT terms through `termSheetView` and `trancheBdtState`, with per-tranche currency, amount, tenor, coupon and maturity blocks. Empty terms are omitted. Bookrunner names and subject currency formatting use the existing projections.
- Generated text has at most 72 characters per line; labels use a 15-character column and values begin at column 18. Legal notices are retained **verbatim**: supplied legal lines longer than 72 remain longer, rather than silently rewriting legal wording.
- Existing send approval, delivery provider, recipient chunking, XML attachment, retry and audit paths are unchanged. The approved email HTML contains the escaped exact MSG text in a monospace `<pre>` followed by the existing terms-table fallback.
- Saved terms and notes update via Realtime; successful local saves also emit `dts:saved`. Unsaved edits are excluded. Channels and listeners are cleaned up on deal switch/unmount.
- CHG highlights use `termsDiff` for historical BDT snapshots. New sends retain their exact MSG text inside the existing approved email snapshot, enabling accurate per-tranche comparisons without adding a new audit store. Legacy sends do not retain a whole-workspace snapshot: unknown historical tranche differences are not invented.
- Existing roles and Co-Pilot functionality are unchanged. The publication-only change enables Realtime without changing permissions; it reaches the app only if this draft is accepted. This draft’s example data never transfers to the app.

## Verification
- 28 formatter/alert/mail tests passed: alignment, 72-column and hanging wrapping, per-tranche amounts/rates, empty omissions, stage-dependent execution values, legal preservation, changed-line comparison and HTML escaping; existing human approval/hash/distribution/chunking tests retained.
- Signed in as the draft’s invented demo account: edited coupon, confirmed no preview change before save, saved via All fields, saw updated coupon immediately and in a second browser window, copied exact text and read saved values back after reload.
- Send update used the same MSG preview with approval disabled; saved commentary updated the second window and survived reload. Test changes restored the original coupon and example commentary. No email or new alert was sent.
- Wide desktop and 390px mobile screenshots checked; mobile page and panel remain within screen width, with horizontal scrolling inside the fixed-width message body.
