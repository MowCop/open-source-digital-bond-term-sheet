## Goal

On Deal Data, add a way to convert a deal (originally created from a chat + AI extraction, with no associated New Issue Bulletin) into a published **New Issue Bulletin** on the New Issue Board, keeping the existing chat thread attached under the same headline (e.g. "The Kingdom of Nania").

## UX

**Trigger (both placements, admins only):**
- Collapsed deal row: a small "Generate Bulletin" icon button next to the trash icon.
- Expanded deal panel header: a "Generate New Issue Bulletin" button next to "Advance to …".
- Both are **hidden / replaced with a "Bulletin published" indicator** when a bulletin already exists for the deal. The indicator links to the bulletin on the New Issue Board.

**Click flow:**
1. Open a confirm modal showing a preview of:
   - Headline (defaults to the deal's existing chat channel label, e.g. "The Kingdom of Nania", editable).
   - Generated bulletin text (AI prose + structured term sheet block, editable textarea).
2. "Publish to New Issue Board" button → creates the bulletin, re-links the chat, navigates to `/messages?messageId=<id>` so the user sees it on the board.

## Bulletin content (AI prose + term sheet)

Generated by a new edge function `generate-bulletin-from-deal` using Lovable AI (`google/gemini-3-flash-preview`).

Input: the full deal record (all populated ICMA fields, bookrunners, stage).

Output (single string of HTML stored in `messages.body`):
1. **AI prose announcement** (2–4 short paragraphs) in standard syndicate-bulletin tone: issuer, ratings, size, tenor, coupon, pricing summary, listing, governing law, bookrunners.
2. **Term Sheet** appended as a clean HTML table of all populated Deal Data fields grouped by Party / Issuer, Issuance, Product (mirrors the existing Deal Data section layout). "TBA" rows are skipped.

The function returns `{ subject, body }`.

## Chat re-linking

The deal already has a `chat_channels` row (created when the deal was chat-extracted). On publish:
- Do **not** create a new thread or copy messages.
- Update the existing channel's `label` to the chosen bulletin headline (so it matches the bulletin subject on the board).
- Store a back-reference from the bulletin to the channel and deal: the new `messages` row uses `dealIds: [deal.id]` (existing field) — that is enough for the New Issue Board to group the channel and bulletin under the same headline, since the board already groups by deal.

No chat messages are duplicated or moved.

## Duplicate prevention

A bulletin "exists for this deal" when there is a `messages` row with `status = 'sent'`, this deal's id in `dealIds`, and a `bulletin_source = 'deal_data'` marker (new column, see below). When present:
- Generate button is hidden in both placements.
- Replaced by a small "Bulletin published" link that navigates to the New Issue Board entry.

## Technical details

**Schema (new migration):**
- Add nullable `bulletin_source text` column to `public.messages` (values: `'deal_data'`, `'manual'`, etc., default null). Used only as a marker; no constraint.
- No new tables.

**Edge function `supabase/functions/generate-bulletin-from-deal/index.ts`:**
- POST `{ dealId }`. Loads the deal via service role, builds a system prompt instructing the model to (a) write a 2–4 paragraph bulletin announcement, (b) append an HTML term sheet table. Uses `streamText`/`generateText` via the shared `ai-gateway` helper (`google/gemini-3-flash-preview`, `max_tokens: 4000`). Returns `{ subject, body }` JSON. CORS + Zod input validation.

**Client (`src/context/AppContext.tsx`):**
- Add action `publishBulletinFromDeal(dealId, { subject, body })`:
  - `createMessage({ subject, body, dealIds: [dealId], recipients: [], status: 'sent', sentAt: now, senderId: currentUser.id, bulletinSource: 'deal_data' })`.
  - If the deal has a `chat_channels` row, call `updateChatChannel(channelId, { label: subject })` (add this helper to `cloudData.ts` if missing).
  - Add an audit log entry: `deal.bulletin_generated`.

**Client (`src/pages/DealsPage.tsx`):**
- Add `FileText` (or `Megaphone`) icon button to collapsed row and expanded header. Hidden when `dealHasBulletin(deal.id)` is true.
- Hook into a new `<GenerateBulletinDialog deal={deal} />` component that:
  1. On open, calls the edge function via `supabase.functions.invoke('generate-bulletin-from-deal', { body: { dealId } })`.
  2. Shows headline + body in editable fields.
  3. On confirm, calls `publishBulletinFromDeal` and navigates to `/messages?messageId=<id>`.

**Types (`src/types/bond.ts`):** add optional `bulletinSource?: 'deal_data' | 'manual'` to `Message`.

**Existing `src/integrations/supabase/cloudData.ts`:** map the new column in `rowToMessage` / `insertMessage` / `updateMessageRow`.

## Out of scope

- No changes to chat message storage or ordering.
- No bulk "generate for all deals" action.
- No editing of the term sheet table structure after publish (it's regenerated only on republish, which is blocked by duplicate prevention).
