# AGENTS
- Digital Term Sheet View reads the live Fill state through src/lib/termSheetView.ts, not saved flat deal columns; empty authoritative fields remain empty — accepted proposals, edits and deletions must agree across tabs without auto-saving.
- New Deal document selection reuses IngestDropzone and existing document readers/extraction service to fill only an empty issuer, guarding against intervening edits; files are handed to the created deal's Fill tab for review of all other proposals — no duplicate parser or auto-acceptance of other terms.
- New Deal defaults and creation eligibility live in src/lib/newDeal.ts and are shared by the button and creation handler — optional fields must not accidentally block creation or introduce fallback bookrunners.
- Digital Term Sheet Fill fields come from the vendored `FIELDS` dictionary and are selected by path through `src/lib/bdt-bridge.ts` — this keeps one definition per field.
- TermSheetField suppresses dictionary example placeholders and preserves full-contrast recorded values in disabled history fields — presentation must not imply that examples are recorded terms or that historical values are absent.
- The expanded-deal Deal Checker renders `unifiedChecks` above the term-sheet tabs — this keeps BDT and VDR rules in one visible validation surface.
- LEI checks are hybrid: the offline MOD 97-10 test is the instant baseline; live GLEIF registry lookups run through the gleif-lookup edge function and are appended to the same Deal Checker list — typing never waits on the network and an outage only downgrades to a warning.
- LEI suggestions from GLEIF name search are shown for the user to pick and are never auto-applied — common names match several legal entities.
- FIGI checks mirror the LEI pattern: offline format/check-digit baseline plus live OpenFIGI lookup via the openfigi-lookup edge function, appended to unifiedChecks with src openfigi; FIGI suggestions are never auto-applied — one source of truth for identifier validation.
- Imperative handles are passed as a plain prop (ingestRef), never React.forwardRef — a default-exported function component that becomes a forwardRef object changes the fiber type and hot reloads blank the preview with "Component is not a function".
- Deal AI tools (document extraction, chat extraction, bulletin) route through supabase/functions/_shared/ai-model.ts, which allowlists the selectable models and calls the gateway's native messages endpoint; the browser only sends the chosen model id from src/lib/aiModel.ts — one place to add or remove models.
- Deal Checker navigation targets and 'Try to fix' repairs live in src/lib/checkActions.ts; fixes only edit the unsaved Fill state (user still saves) and ignored warnings are stored per deal in the browser — one place for checker actions, nothing auto-saved.
- Files dropped on a deal are stored in the private deal-documents bucket and indexed in public.deal_documents (src/lib/dealDocuments.ts), added to the unsaved term sheet Documentation list on drop (user still saves), and counted by the Deal Checker as attached — one store for deal files.

- reference/deal-checker-capabilities.md is the living summary of Deal Checker checks and knowledge sources; any change to Deal Checker rules, fixes or sources must review and update it in the same change — keeps the knowledge base accurate.
- The Al Rajhi demo deal (seed, chat replay script, term sheet stage snapshots) is defined only in src/data/alRajhiDemo.ts and driven by src/components/AlRajhiDemoPanel.tsx — one source for the demo flow; replayed messages go through the normal Fill parser, never auto-accepted.
- Al Rajhi board bodies use Word-derived reference HTML while replay parsing uses plain text; legacy generated bodies are projected at display time without database writes or overwriting user edits — preserve original document structure and stage timing.
- Board-to-term-sheet links use src/lib/dtsNavigation.ts to resolve the selected update's deal, stage and publication time; Fill reads saved stage snapshots without modifying lifecycle or terms, and reports missing snapshots rather than inventing history — both board toolbars must share this navigation contract.
